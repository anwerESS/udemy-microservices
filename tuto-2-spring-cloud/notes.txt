	- configure a Spring Cloud Config Server:
		* from a class path
			1. In your Config Server project, add the following dependencies to your pom.xml
				<dependency>
					<groupId>org.springframework.cloud</groupId>
					<artifactId>spring-cloud-config-server</artifactId>
				</dependency>
				...
			  <dependencyManagement>
				<dependencies>
				  <dependency>
					<groupId>org.springframework.cloud</groupId>
					<artifactId>spring-cloud-dependencies</artifactId>
					<version>${spring-cloud.version}</version>
					<type>pom</type>
					<scope>import</scope>
				  </dependency>
				</dependencies>
			  </dependencyManagement>
			2.  Enable the Config Server with @EnableConfigServer in main class
			3.  Configure the Config Server to Use Classpath (application.yml)
				server:
				  port: 8888  # Default port for Config Server

				spring:
				  profiles:
					active: native  # Use the "native" profile to load from classpath
				  cloud:
					config:
					  server:
						native:
						  search-locations: classpath:/config  # Look for config files in /config directory on classpath
			4. Add Configuration Files to the Classpath
				└── config
					├── accounts-prod.yml
					├── accounts-qa.yml
					├── accounts.yml
					├── cards-prod.yml
					├── cards-qa.yml
					├── cards.yml
					├── loans-prod.yml
					├── loans-qa.yml
					└── loans.yml
			5. Start the Config Server
			6. Access the Config Server from a Client (application.yml)
				spring.config.import : "optional:configserver:http://localhost:8f071"

	- refresh config at runtime
		* using refresh actuator path
			1. add acutuator dependency in pom.xml
			2. add refresh actuator path in application.yml
				management:
				  endpoints:
					web:
					  exposure:
						include: refresh
			3. curl http://localhost:8080/actuator/refresh
				[
					"config.client.version",
					"accounts.message"
				]
		* refresh config using spring cloud bus
			1. add spring cloud bus dependency in pom.xml
			    <dependency>
                  <groupId>org.springframework.cloud</groupId>
                  <artifactId>spring-cloud-starter-bus-amqp</artifactId>
                </dependency>
			2. add refresh actuator path in all application.yml
				spring:
				  rabbitmq:
					host: "localhost"
					port: 5672
					username: "guest"
					password: "guest"
				management:
				  endpoints:
					web:
					  exposure:
						include: busrefresh
			3. docker run -it --rm --name rabbitmq -p 5672:5672 -p 15672:15672 rabbitmq:4.0-management
			4. http://localhost:8080/actuator/refresh
		* refresh config using spring cloud bus & spring cloud config monitor
			1. add spring cloud config monitor dependency in pom.xml (this will expose /monitor endpoint)
				<dependency>
				  <groupId>org.springframework.cloud</groupId>
				  <artifactId>spring-cloud-config-monitor</artifactId>
				</dependency>
			2. add refresh actuator path in all application.yml
				spring:
				  rabbitmq:
					host: "localhost"
					port: 5672
					username: "guest"
					password: "guest"
				management:
				  endpoints:
					web:
					  exposure:
						include: busrefresh
			3. docker run -it --rm --name rabbitmq -p 5672:5672 -p 15672:15672 rabbitmq:4.0-management
			4. set up a webhook in github to call http://<host>:8071/monitor

	- shutting down a microservice
		* add the fllowing configuration in application.yml
			management:
			  endpoint:
				shutdown:
				  enabled: true  # Enable the shutdown endpoint.
			  endpoints:
				web:
				  exposure:
					include: shutdown  # Expose the shutdown endpoint over HTTP.
		* http://localhost:8080/actuator/shutdown
		* benefits of shutting down a microservice over kill it:
			1. microservice stopped gracefully (Stop accepting new requests, Complete ongoing requests...etc)
			2. Clean Resource Release
			3. No Interrupted Operations
			4.Better for Debugging and Monitoring

	- Implement Feign Client to invoke other microservices
		* add in pom.xml
			<dependency>
			  <groupId>org.springframework.cloud</groupId>
			  <artifactId>spring-cloud-starter-openfeign</artifactId>
			</dependency>
		* add @EnableFeignClients in AccountsApplication
		* create interfaces in service package for others microservices
			@FeignClient("cards")  // Declares this interface as a Feign client for the "cards" service.
			// The "cards" service is the name of the remote service registered in the service registry (e.g., Eureka).
			public interface CardsFeignClient {

				@GetMapping(
						value = "/api/fetch",  // Specifies the endpoint path on the remote service.
						consumes = "application/json"  // Specifies that the request and response will be in JSON format.
				)
				public ResponseEntity<CardsDto> fetchCardDetails(@RequestParam String mobileNumber);  // Defines a method to call the remote API.
				// The method sends a GET request to `/api/fetch` with a `mobileNumber` query parameter.
				// The response is wrapped in a `ResponseEntity` containing a `CardsDto` object.
			}
